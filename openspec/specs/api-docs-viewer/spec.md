# Delta for api-docs-viewer

## ADDED Requirements

### Requirement: Scalar Doc Viewer Route Registration

The system MUST serve an interactive Scalar API documentation viewer at `GET /reference`. The viewer SHALL render the same OpenAPI document produced by `@nestjs/swagger` and remain available for the lifetime of the running application.

#### Scenario: Scalar viewer responds at /reference

- GIVEN the application is running with Scalar registered
- WHEN a client sends `GET /reference`
- THEN the response status is 200
- AND the response body contains Scalar's interactive documentation UI

#### Scenario: Scalar viewer returns 404 when not registered

- GIVEN the application is running without Scalar middleware registered
- WHEN a client sends `GET /reference`
- THEN the response status is 404

### Requirement: OpenAPI Spec Consumption

Scalar MUST consume the exact same OpenAPI document generated by `@nestjs/swagger`'s `SwaggerModule.createDocument()`. All endpoints, schemas, tags, and metadata visible in Swagger UI SHALL be identically rendered by Scalar.

#### Scenario: Scalar renders all existing endpoints

- GIVEN the application has an OpenAPI document with registered endpoints
- WHEN a client opens `GET /reference`
- THEN Scalar displays every endpoint defined in the OpenAPI document
- AND endpoint details (parameters, responses, schemas) match the Swagger UI output

#### Scenario: Scalar reflects OpenAPI document changes at startup

- GIVEN a new controller endpoint is added to the application
- WHEN the application restarts and a client opens `GET /reference`
- THEN Scalar displays the newly added endpoint
- AND the endpoint specification matches the OpenAPI document

### Requirement: Swagger UI Backward Compatibility

The system MUST continue serving Swagger UI at `GET /docs` unchanged. Registering Scalar SHALL NOT alter, redirect, or disable the existing Swagger UI route.

#### Scenario: Swagger UI remains accessible at /docs

- GIVEN both Scalar and Swagger UI are registered
- WHEN a client sends `GET /docs`
- THEN the response status is 200
- AND the response body contains Swagger UI

#### Scenario: Both viewers operate independently

- GIVEN both viewers are registered on separate routes
- WHEN a client sends `GET /docs` and `GET /reference` in sequence
- THEN each route returns its respective viewer UI
- AND neither route's response contains content from the other viewer

### Requirement: NestJS Fastify Integration

Scalar middleware MUST mount via `app.use()` on the Fastify adapter without requiring additional Fastify plugins or adapter-specific configuration. The integration SHALL use the same `SwaggerModule.createDocument()` output already available in `src/main.ts`.

#### Scenario: Scalar mounts with app.use on Fastify adapter

- GIVEN a NestJS application using the Fastify adapter
- WHEN Scalar is registered via `app.use('/reference', apiReference({ spec: { content: swaggerDocument } }))`
- THEN `GET /reference` serves the Scalar UI
- AND no additional Fastify plugins are required

#### Scenario: Scalar registration does not interfere with existing middleware

- GIVEN the application has existing middleware and Swagger UI registered
- WHEN Scalar middleware is added via `app.use()` after Swagger setup
- THEN all existing routes and middleware continue functioning
- AND no route conflicts or middleware ordering issues occur
